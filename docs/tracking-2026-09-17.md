# NOCTE tracking matching, 2026-09-17

Production baseline: `99ff9d0`. Frontend project `nocte`, backend project `n0ct3` (root `nocte-backend`). These are separate deployments of the same repository.

## Change

- CAPI mirror now preserves SHA-256 `ct`, `st`, and `country`. The previous allowlist silently discarded city and country sent by the browser.
- Department is looked up from the checkout city, using the same finite JSON catalog in browser and server. It is hashed before forwarding to Meta. Asunción is separate from Central; Yaguarón maps to Paraguarí. Bare Bella Vista and unknown/free-text locations are omitted rather than guessed. No extra checkout fields.
- Browser city hashing agrees with server hashing (lowercase, no accents, punctuation, spaces or digits). Country remains `py`. Existing surname extraction is retained and tested on both paths; a single full-name field cannot reliably disambiguate compound given names and surnames. No speculative new name parser.
- The optional IPv6 lookup runs once per page, in the background, against `https://api6.ipify.org`, with a 1.5-second timeout, omitted credentials and no referrer. Only the public IP is requested; no order or customer fields are sent to the resolver. Result stays in memory, expires after five minutes, and is never awaited by checkout or event delivery.
- The browser sends `client_ipv6` as a separate optional hint. The backend accepts only a valid global-unicast IPv6, excludes documentation/private/link-local/scoped addresses, prefers a native observed IPv6, and otherwise retains the request IP. The hint is used only for Meta matching, never authentication, rate limiting or routing. `META_CLIENT_IPV6=off` disables hint consumption after redeploy.
- The frontend CSP allows only the exact additional resolver origin in `connect-src`. No external scripts or new production dependencies.

No changes to campaign configuration, pixel ID, order persistence, payment charging, event names, purchase IDs/deduplication, amount/currency, cookies, or browser fallback. Older clients work with the new backend. New clients also work with the old backend (additional fields are ignored).
